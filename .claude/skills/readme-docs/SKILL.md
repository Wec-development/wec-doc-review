# README standards

1. Written for an engineer joining the project: short, specific, no filler.
2. Required sections: how to run it and what to click first; monorepo layout and why; schema and how versions, values and reviews relate; how extraction is coordinated; open decisions and what was chosen and why; what was cut and what is next; what changes at 10,000 documents.
3. Document the decisions: correction model, what "unchanged evidence" means, new version during extraction, polling choice.
4. Every command in the README must actually work — run it before writing it.
5. Keep README in sync with code in the same PR that changes behaviour.
